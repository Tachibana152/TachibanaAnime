## ② AI 流式聊天接口（Route A：langchain4j-reactor + Flux）

**Q：Flux\<String\> 可以实现流式输出吗？与之前的 SseEmitter 方案区别？**

- **选型（路线 A）**：langchain4j 官方支持 `Flux` 作为 `@AiService` 返回类型（需引入 `langchain4j-reactor` 模块），内部用 `TokenStreamToFluxAdapter` 把 `TokenStream` 回调桥成 `Flux`（`Sinks.many().unicast().onBackpressureBuffer()`，onPartial/onComplete/onError 自动处理 + 会话记忆）
- 对比 `SseEmitter`：两者前端协议一致（`text/event-stream` + `data:` 帧）；Flux 代码更少、取消语义由框架处理；已知缺口是 Flux 中途取消不终止底层 SSE 请求（langchain4j issue #5275），演示规模可接受
- **实现**：
  - `pom.xml` 加 `langchain4j-reactor:1.19.0-beta29`
  - `Assistant.chatStream` 返回类型 `TokenStream` → `Flux<String>`（@MemoryId + RAG ContentRetriever 自动注入）
  - 新增 `AIService/dto/ChatDTO`（sessionId + message，@NotBlank）、`AIService/service/AIChatService`(+Impl，委托 Assistant)、`AIService/controller/AIChatController`
  - `POST /api/ai/chat`（同步 → `R<String>`）；`POST /api/ai/chat/stream`（`produces=text/event-stream` → `Flux<String>` 直接透传）
  - 不加 `@NoAuth`，由 `AuthInterceptor` 统一鉴权（需登录）
- **SSE 帧格式实证**：项目是 Spring MVC（servlet），Controller 返回 `Flux<String>` 由 `ReactiveTypeHandler` 适配；反编译 `spring-webmvc 7.0.7` 验证走 `SseEmitter`，`SseEventBuilderImpl.build()` 输出 `data: xxx\n\n`（`data:` 前缀 + 空行分隔），与前端解析契约一致

## ③ 前端 AI 聊天页

- **`frontend/src/api/ai.js`**：`chat()` 走 axios；`chatStream()` 用 `fetch`（POST + `Authorization: Bearer`）+ `ReadableStream` 拆帧
  - 为什么不用原生 `EventSource`：登录鉴权要带 `Authorization` 头，而 `EventSource` 无法自定义请求头
  - 解析逻辑：`resp.body.getReader()` 逐块读 → `TextDecoder` 解码 → 按 `\n\n` 切帧 → 取 `data:` 行 → `onToken`；兼容无 `data:` 前缀的裸 chunk
- **`views/AIChatView.vue`**：消息气泡 + 打字机光标 + 会话 ID 切换（记忆隔离）+ 清空对话 + 回车发送（Shift+Enter 换行）
- 路由 `/ai`（`meta.requiresAuth`）+ `MainLayout` 顶栏加「AI 助手」入口
- `mock/index.js` 加 `chat` 模拟回复 + 前端 mock 打字机（无后端也可演示）

## ④ 排坑①：网页提问显示「（无回复）」

**Q：为什么在网页问问题显示（无回复）？**

- **现象**：浏览器提问后立刻显示「（无回复）」（`AIChatView.onDone` 空内容兜底文案）
- **排查**：反编译 spring-webmvc 7.0.7 确认 `ReactiveTypeHandler` 对 `text/event-stream` 用 `SseEmitter` 输出 `data: xxx\n\n` —— **前端解析器无问题**
- **根因**：SSE 响应头发出后，若后端模型调用异常，`TokenStream.onError → sink.tryEmitError → Flux 出错 → MVC 关闭连接`；但 HTTP 层面连接是「正常结束」的，`fetch` 读到流结束 → 走 `onDone` → 空内容 → 显示「（无回复）」。**SSE 的"中途异常"对 fetch 不可见，前端把异常关闭误当成空回复**
- 后端日志实锤：`ResourceAccessException: I/O error on POST https://api.openai.com/...: Connection timed out`

## ⑤ 排坑②③：网关配置（base-url / 模型名）

**Q：修改 base-url 后报 ModelNotFoundException（404），怎么回事？**

- **② 404 根因**：`base-url: https://opencode.ai/zen/go/v1/responses` 多了一截 `/responses`。langchain4j-open-ai 会在 base-url 后拼 `/chat/completions`，实际请求 `.../v1/responses/chat/completions` → 网关 SPA 404 页 → `ModelNotFoundException`。**实测**：带 `Bearer` 头 POST `https://opencode.ai/zen/go/v1/chat/completions` 返回 401（路由存在、需鉴权）→ 正确基址是去掉 `/responses`
- **③ 500 根因**：`GET https://opencode.ai/zen/go/v1/models` 返回可用模型列表（minimax/kimi/glm/deepseek/qwen/mimo 系列），**没有 `gpt-5.6-luna`** → 请求该模型时网关 500 `Internal server error`
- **修复**：`application-local.yml` 的 `chat-model` / `streaming-chat-model` 均改 `base-url: https://opencode.ai/zen/go/v1` + `model-name: deepseek-v4-flash`
- **教训**：OpenAI 兼容网关配置三要素 —— base-url 必须是「能拼出 `/chat/completions` 的根地址」、模型名必须在网关 `/models` 列表内、api-key 需对应该网关

## ⑥ 错误可见化（治本 UX）

- **`AIService/AiErrorUtil.java`**（新增）：把 langchain4j 异常收敛成友好中文提示（鉴权失败 / 404 base-url / HTTP 状态码 / 连接失败 / HTML 原文兜底截断）
- **`AIChatServiceImpl.chatStream`**：`.onErrorResume(e -> Flux.just("[error] " + AiErrorUtil.friendly(e)))` + `@Slf4j` 记录 —— 不再静默关连接，把错误推给前端
- **`GlobalExceptionHandler`**：新增 `@ExceptionHandler(LangChain4jException.class)`（同步路径友好提示）
- **前端 `ai.js`**：识别 `[error]` 开头帧 → 走 `onError`（而非 onToken）；`AbortController` 90s 超时 → 提示「请求超时」
- **`AIChatView.vue`**：错误渲染为红色气泡展示真实原因，替代「（无回复）」
