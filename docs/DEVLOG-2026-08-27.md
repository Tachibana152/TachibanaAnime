## ② 权限实现：`@RequireRole` 拦截器校验

**Q：具体实现步骤是什么。** → 实现 `AuthInterceptor`：

- 反射读方法级 `@RequireRole`，无则取类级（方法级覆盖类级）
- 取 `UserContext.getRole()`（来自 JWT claims）与 `value()` 允许集合比对
- 不匹配 → 新增 `writeForbidden` 返回 403 `R.fail(ResultCode.FORBIDDEN)`

**效果**：一处修改，所有已声明的 `@RequireRole` 统一生效（AdminUserController 仅超管、AdminPostController/AnimeController 增删改需管理员+）。联调实测：USER 调 admin 接口 → **403**。

## ⑥ Redis 集成（三用途落地）

### 登录态（A 方案，JWT + Redis 双校验）
- `AuthServiceImpl.login`：写 `login:token:{userId}`(7200s) + `login:user:{userId}`(3600s，存 `UserVO` 不含密码)
- `AuthInterceptor`：JWT 通过后比对 `login:token`，不一致 → 401（登出/禁用/顶号立即失效）
- `application.yml` 加 `security.redis-session.enabled`（默认 true，false 退回纯 JWT）

### 热点缓存
- 动漫详情 `cache:anime:{id}`(600s)、帖子详情 `cache:post:{id}`(300s)；更新/删除/审核时 DEL

### 浏览量计数
- `count:anime:{id}` / `count:post:{id}` INCR + DB `view_count+1` 同步

### 方案 B：改角色即时生效（重要决策）
- **问题**：JWT 的 role claim 登录时签发不可改，改 DB 角色后旧 token 权限判断仍按旧角色
- **方案 A**：删 token 强制重登（会踢下线）；**方案 B（选定）**：`AuthInterceptor` 角色改从 `login:user:{id}` 缓存读取（有缓存用缓存，没有回退 JWT claim）
- **实测**：USER 改 ADMIN 后**不重登**直接访问 admin 接口 → 200 ✅

## ⑦ 排坑记录（今日关键）

### 踩坑①：Redis 序列化器缺 JavaTimeModule → 登录/详情 500
- 现象：登录返回 500「系统内部错误」，但列表接口正常
- 原因：`RedisConfig` 用 `new GenericJackson2JsonRedisSerializer()`（默认 ObjectMapper 无 `JavaTimeModule`），写含 `LocalDateTime` 的 `SysUser/AnimeVO/PostVO` 时序列化失败
- 修复：`RedisConfig` 用带 `JavaTimeModule` + 默认类型信息的 ObjectMapper 构造序列化器

### 踩坑②（根因级）：Redis 密码 YAML 数值解析坑 → WRONGPASS
- 现象：直连 TCP 用 `07210721` 认证 `+OK`，但应用认证 `WRONGPASS`
- 原因：`password: 07210721` 以 `0` 开头，SnakeYAML 按**十进制整数**解析成 `7210721`（丢前导 0），绑定为字符串密码即错
- 对照实验证明：显式 `--spring.data.redis.password=07210721`（字符串）→ 登录 200
- 修复：`application-local.yml` 密码加引号 `password: "07210721"`
- 教训：**YAML 中 `0` 开头且可能被当数字的字符串值必须加引号**

### 踩坑③：mvnw/Start-Process 启动测试的端口与进程管理
- `spring-boot:run` 杀 mvnw 进程不会杀其子 java 进程 → 残留占用端口
- 改用 `mvnw package` + `java -jar` 直接启动，并在脚本末尾按命令行特征清理残留 java 进程
- 8080 被用户 IntelliJ 实例占用，独立测试实例用 18086 等空闲端口

### 踩坑④：PowerShell 调 curl.exe 的坑
- `curl.exe -d '{"..."}'` JSON 双引号被 PowerShell 转义破坏 → 后端 400「请求体格式错误」
- `Invoke-RestMethod -Form` 在 Windows PowerShell 5.1 **不支持**
- 对策：JSON 用 `Invoke-RestMethod -ContentType application/json`；multipart 用 `curl.exe -F "file=@path"`

### 踩坑⑤：Tomcat `transferTo` 相对路径 → 文件上传 500
- 现象：`file.transferTo(Paths.get("uploads/").resolve(name).toFile())` 抛 IOException「文件保存失败」
- 原因：Spring Boot + Tomcat 的 `Part.write(String)` 把**相对路径解析到 Tomcat 自己的 multipart 临时目录**，该目录无 `uploads` 子目录 → FileNotFoundException
- 修复：`Paths.get(uploadDir).toAbsolutePath()` + `Files.copy(getInputStream(), target, REPLACE_EXISTING)`（绕开相对路径解析）
- 实测：上传 200 + `/uploads/xxx` 静态访问 200

### 踩坑⑥：联调脚本函数返回值被 Write-Output 污染
- PowerShell 函数会捕获函数内所有 Write-Output，导致返回值变成数组、数据取不到
- 修复：显示信息改用 `Write-Host`（走信息流，不进输出流）
