## ① langchain4j 集成修复

**Q：langchain4j 配置怎么改？gpt5.6luna 的官方名是什么？**

- 官方模型 ID：**`gpt-5.6-luna`**（全小写、连字符）；`GPT 5.6 Luna`（带空格大写）会被 API 判定不存在
- `max-tokens: 128000` 是 `gpt-5.6-luna` 的**输出上限**，合法（早前误判为超限，已更正）
- 依赖问题：
  - 项目是 Spring Boot **4.1.1**，官方 Boot4 需用 `langchain4j-open-ai-spring-boot4-starter`（Boot3 变体不兼容）；`1.10.0-beta18` 无 Boot4 变体，升级 **`1.19.0-beta29`**
  - `@AiService`/`@SystemMessage` 注解来自 **`langchain4j-spring-boot4-starter`**（AI Service starter，非 open-ai starter）——缺它 `@AiService` 无法解析
- `application-local.yml`（已 gitignore）：`model-name: gpt-5.6-luna` + `temperature`/`timeout`/`streaming-chat-model` 等参数

**踩坑记录①**：`@AiService` 接口缺 import 报"找不到注解"，根因是漏了 `langchain4j-spring-boot4-starter` 依赖。

## ② Redis 序列化器迁移（Spring Data Redis 4.0 废弃 API）

**Q：`GenericJackson2JsonRedisSerializer` 自 4.0 起已弃用并标记移除。**

- 替代品：**`GenericJacksonJsonRedisSerializer`**（注意少一个 `2`，Jackson **3** 版，`@Deprecated(since="4.0", forRemoval=true)`）
- Jackson 3 已将 JSR-310 支持**并入 jackson-databind 核心**，**无需再注册 JavaTimeModule**（官方 modules-java8 文档明确）
- builder 的 `enableUnsafeDefaultTyping()` 复刻旧行为：`NON_FINAL + As.PROPERTY + Id.CLASS`，类型属性名仍为 `@class`，**与旧数据格式兼容**，Redis 存量会话/缓存无需迁移
- 改动：`config/RedisConfig.java`（`jsonSerializer()`）+ `AIService/config/JsonRedisTemplate.java`（未使用组件，同步迁移）
- 验证：登录 + `me()` 读回含 `LocalDateTime`（`createTime=2026-01-01T10:00:00`）的用户信息正常

## ③ AI 会话记忆

**Q：`private final JsonRedisTemplate redisTemplate;` 这是什么？**

- `JsonRedisTemplate`：Spring Data Redis 提供的 Redis 模板（value 走 JSON 序列化）；字段用**构造器注入**（项目惯例），由 Spring Boot `RedisAutoConfiguration` 自动提供 bean
- 注意：项目 `RedisConfig` 自定义的是 `RedisTemplate<String, Object>`，与 `JsonRedisTemplate` 是两个不同的 bean

- **`RedisChatMemoryStore`**：实现 langchain4j `ChatMemoryStore`，把 AI 会话历史持久化到 Redis（key `chat:memory:{memoryId}`，JSON 存取）；raw type 字段已改为 `RedisTemplate<String, Object>` 消除警告
- **`ChatMemoryConfig`**：`ChatMemoryProvider` → 每个 `@MemoryId` 会话一个 `MessageWindowChatMemory`（**maxMessages=20** 滑动窗口），重启不丢

## ⑤ 动画 → RAG 向量库

**Q：提交动画作品详情后，将该动画信息提交到向量数据库，从而加入 RAG？**

- **`RagIndexUtil`**（`AIService/rag/`）：文档切分（recursive 500/100）→ bge 嵌入 → 以**确定性 id 覆盖写入**（`JSON.SET` 同 key 覆盖不重复）+ 前缀扫描清理
  - 向量 id：动画 `anime:{id}:{i}`；文档 `doc:{文件名}:{i}`
- **`AnimeRagIndexer`**：`indexAnime(Anime)`（拼接标题/日文名/分类/制作阵容/简介/内容/语录等全部文本 → 入库）、`removeAnime(id)`（前缀清理）；内部 try/catch，**向量库异常不影响动漫 CRUD 主流程**
- **`AnimeServiceImpl`** 三处接入：`create()` insert 后 `indexAnime`；`update()` 后重新查询并 `indexAnime`；`delete()` 后 `removeAnime`
- **关键改造**：`easyRagIngestor` 去掉全局 `embeddingStore.removeAll()`（否则每次重启会**清掉运行时新增的动画向量**），改为 rag-docs 按 `doc:{文件名}` 确定性覆盖

**验证结果**：
- 新增动画 id=20 → Redis 出现 `embedding:anime:20:0` ✅
- **重启后端** → `embedding:anime:20:0` 仍在（不再被启动流程清空）✅
- 删除动画 → `embedding:anime:20:*` 清空（TOTAL=0）✅
- rag-docs 重复重启仅 1 条 `embedding:doc:sample:0`（无重复）✅
